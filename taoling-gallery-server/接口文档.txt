一、接口模块总览

你的项目建议分成 9 个接口模块：

1. Auth 认证模块
2. User 用户个人中心模块
3. Public Image 前台图库模块
4. Favorite 收藏模块
5. Download 下载记录模块
6. AI Chat 桃灵助手模块
7. Admin Dashboard 管理首页模块
8. Admin Content 图片 / 分类 / 标签管理模块
9. Admin User 用户管理模块

不需要设计的接口：

关注接口
粉丝接口
作品集接口
用户发布图片接口
用户作品管理接口
PRO 会员接口
系统设置接口
内容举报接口
用户关注创作者接口
创作者计划接口
二、通用接口规范
1. 基础路径
/api
2. 通用返回格式
{
  "code": 200,
  "message": "success",
  "data": {}
}

列表分页返回：

{
  "code": 200,
  "message": "success",
  "data": {
    "list": [],
    "pagination": {
      "page": 1,
      "pageSize": 12,
      "total": 100
    }
  }
}
3. 权限标识

请求头：

Authorization: Bearer jwt_token

权限类型：

游客：不传 token
普通用户：token 中 role = user
管理员：token 中 role = admin
三、Auth 认证模块

认证模块对应页面：

登录 / 注册页

对应数据库：

users
user_stats
admin_logs
1. 注册
POST /api/auth/register

权限：

游客可访问

请求参数：

{
  "username": "hetao",
  "email": "test@example.com",
  "password": "123456"
}

后端逻辑：

1. 校验 username 是否唯一
2. 校验 email 是否唯一
3. 密码加密生成 password_hash
4. 写入 users，默认 role = user，status = normal
5. 初始化 user_stats
6. 写入 admin_logs：USER_REGISTER

返回：

{
  "id": 1,
  "username": "hetao",
  "email": "test@example.com",
  "role": "user"
}
2. 登录
POST /api/auth/login

权限：

游客可访问

请求参数：

{
  "account": "hetao",
  "password": "123456"
}

说明：

account 可以是 username 或 email

后端逻辑：

1. 查询 users
2. 判断 deleted_at IS NULL
3. 判断 status = normal
4. 校验密码
5. 更新 last_login_at
6. 查询 user_stats
7. 生成 token
8. 写入 admin_logs：USER_LOGIN

返回：

{
  "token": "jwt_token",
  "user": {
    "id": 1,
    "username": "hetao",
    "email": "test@example.com",
    "role": "admin",
    "status": "normal",
    "avatar_url": "https://xxx.com/avatar.png",
    "last_login_at": "2026-06-04 20:00:00",
    "created_at": "2026-06-01 10:00:00"
  },
  "stats": {
    "favorite_count": 12,
    "download_count": 8,
    "view_count": 36,
    "ai_conversation_count": 5,
    "ai_message_count": 42
  }
}
3. 退出登录
POST /api/auth/logout

权限：

登录用户

说明：

JWT 本身无状态，前端删除 token 即可。
后端只负责写入 admin_logs：USER_LOGOUT。
4. 获取当前登录用户
GET /api/auth/me

权限：

登录用户

用途：

刷新页面后恢复用户信息
判断当前用户是 admin 还是 user

返回：

{
  "user": {
    "id": 1,
    "username": "hetao",
    "email": "test@example.com",
    "role": "admin",
    "status": "normal",
    "avatar_url": "https://xxx.com/avatar.png"

    "favorite_count": 12,

3. 记录图片浏览
POST /api/images/:id/view

权限：

游客 / 登录用户都可以访问

请求参数：

{
  "visitor_id": "guest_uuid_123"
}

后端逻辑：

1. 校验图片存在
2. 校验图片 status = public
3. 写入 image_view_records
4. images.view_count + 1
5. 如果是登录用户，user_stats.view_count + 1
6. 可选写入 admin_logs：IMAGE_VIEW

为什么单独设计这个接口：

GET /api/images/:id 只负责获取详情。
POST /api/images/:id/view 负责产生浏览记录。
这样更符合接口规范，避免 GET 接口产生写操作。

登录用户

1. 校验用户已登录

3. 删除单条下载记录
DELETE /api/user/downloads/:id

权限：

登录用户

后端逻辑：

UPDATE download_records
SET deleted_at = NOW()
WHERE id = ?
AND user_id = 当前用户
AND deleted_at IS NULL

注意：

不减少 images.download_count
不减少 user_stats.download_count
4. 清空下载记录
DELETE /api/user/downloads

权限：

登录用户

后端逻辑：

当前用户所有 download_records.deleted_at = NOW()

注意：

只清空个人展示记录，不影响历史累计下载数。

1. 发送 AI 消息
POST /api/ai/chat

权限：

登录用户

请求参数：

{
  "conversation_id": 1,
  "message": "帮我找一张治愈风的水彩插画，要有小猫"
}

说明：

conversation_id 可选。
如果不传，后端自动创建新会话。

后端逻辑：

1. 校验登录
2. 如果没有 conversation_id，创建 ai_conversations
3. 保存用户消息 role = user
4. 调用大模型
5. 根据 AI 意图查询 images / tags
6. 保存 AI 回复 role = assistant
7. 保存 recommended_tags / recommended_image_ids
8. 如果是新会话，AI 自动生成 title
9. 更新 user_stats.ai_message_count
10. 如果是新会话，更新 user_stats.ai_conversation_count
11. 写入 admin_logs：
    AI_CONVERSATION_CREATE
    AI_MESSAGE_SEND
    AI_MESSAGE_REPLY
    AI_TITLE_GENERATE

返回：

{
  "conversation_id": 1,
  "title": "治愈风小猫插画",
  "reply": "我帮你找到了一些治愈风、水彩、小猫相关的灵感图片。",
  "recommended_tags": ["治愈系", "水彩风", "小猫"],
  "recommended_images": [
    {
      "id": 1,
      "title": "春天小猫水彩插画",
      "thumbnail_url": "https://xxx.com/thumb.jpg",
      "image_url": "https://xxx.com/image.jpg"
    }
  ]
}

权限：

管理员

请求参数：

{
  "title": "新的图片标题",
  "description": "新的图片描述",

  "thumbnail_url": "https://xxx.com/new_thumb.jpg",
  "category_id": 2,
  "aspect_ratio": "1:1",
  "status": "private",
  "display_weight": 60,
  "tag_ids": [2, 4, 5]
}

后端逻辑：

1. 更新 images
2. 对比旧 tag_ids 和新 tag_ids
3. 新增缺失的 image_tags
4. 删除不再需要的 image_tags
5. 对 tags.usage_count 做增减
6. 写入 admin_logs：IMAGE_UPDATE

说明：

修改图片状态 public / private / draft 也走这个接口。
不需要单独设计一个“修改状态接口”，避免冗余。
